# The kannadi command-line tool

The `kannadi` binary in `crates/kannadi-cli` converts files and folders in both directions, normalizes Unicode text (see [Normalization](library.md#normalization)), and shows Kannada words for words typed in English letters (`kannadi type`):

```sh
cargo install --path crates/kannadi-cli
kannadi to-unicode old-orders/ --out converted/
kannadi to-nudi letter.txt --out for-printing/ --strict
kannadi type namaskara
```

- A file goes to `OUT/<file name>`. A folder goes to `OUT/<folder name>/`, with its subfolders kept. Hidden files, files already under `OUT`, and symbolic links to folders are skipped. The tool stops before writing anything if an output would overwrite any input or 2 inputs would share an output; paths are compared with links and `..` resolved, ignoring case.
- Text files with a UTF-16 or UTF-8 byte order mark, or valid UTF-8, are read as such. Other legacy text files are read as Windows-1252. `to-unicode` decides line by line: lines that `legacy::is_unicode` accepts are kept, so their English words stay English, and the other lines are converted. A line of ASCII alone goes with the file as a whole. Kept lines get only likely typos in the report, and keep a typed zero as it is. Unicode output is UTF-8. Nudi output is Windows-1252, with `?` for each character that has no glyph; those characters are in the report.
- When a file has unknown glyphs, malformed syllables, unencodable characters or likely typos, the tool writes `FILE.report.tsv` next to the output: the line, the problem, and up to 30 characters of Unicode text on each side. Rows are in line order. A run with none removes an old report. Likely typos come from `typos::find` on the text `to-unicode` writes, such as `ಋ for ರೃ (ra-vocalic-r)`. They are suggestions and do not count as problems. Nudi's ಋ with an arkavattu gets 2 rows: a malformed syllable, since an arkavattu cannot sit on a vowel letter, and the likely typo `ಋ for ರ್ಋ`.
- Exit status: 0 on success, even when reports list problems or likely typos; 1 with `--strict` when a file has a problem; 2 for bad arguments, or a file that could not be read, converted or written (a PDF, DOC or RTF file given to `to-nudi` is one). 2 wins over 1. After a file fails, the other files are still converted. If an output would overwrite an input, nothing is written.
- `kannadi --help` and `kannadi to-unicode --help` give every option, with examples. `kannadi completions bash` (or `zsh`, `fish`, `powershell`, `elvish`) prints a completion script, and `kannadi manpages DIR` writes the man pages. Copies of both are in [crates/kannadi-cli/assets](../crates/kannadi-cli/assets). Packagers install them as `share/man/man1/*.1`, `share/bash-completion/completions/kannadi`, `share/zsh/site-functions/_kannadi` and `share/fish/vendor_completions.d/kannadi.fish`.
- `to-unicode` takes `--kannada-digits` and `--keep-zeros`, the same settings as `legacy::Options`.
- **HTML.** Only text set in a legacy font is converted to Unicode, in that font's layout. The font of each piece of text comes from its `style` attribute, then `<style>` rules for tags and classes such as `td.xl24` or `.font12` (the most specific, then the last), then `<font face>`, inherited from enclosing elements. End tags HTML lets authors leave out, such as `</td>` and `</p>`, are closed where a browser would close them. Legacy font names are replaced with `--font` (Noto Sans Kannada by default). `to-nudi` converts Kannada text outside legacy fonts and wraps it in a span set in `--font` (Nudi 01 e by default); the rest of the text is copied as it was. A page that declares a Windows-1252 or ISO-8859-1 charset is read that way. Output is UTF-8, and the charset declaration says so. Text in `<title>`, `<textarea>` and attribute values is not converted, and a syllable split across tags is converted piece by piece, so it shows as malformed in the report. More complex selectors and the `font` shorthand are not read.
- **DOCX.** A run's font comes from its own `w:rFonts`, its character style, its paragraph style (or the default paragraph style), or the document defaults, following `basedOn`. Only runs whose Latin font is a legacy font are converted to Unicode, in that font's layout. Their fonts are set to `--font`. Word often splits a word across runs; text is moved between neighboring runs so no syllable is split. `to-nudi` moves each Kannada run of text into a new run set in `--font`, with the rest of the run's formatting. The body, headers, footers, footnotes, endnotes and comments are converted; every other part of the package is copied unchanged. Report rows name the part and paragraph; the fallback copy of a text box is converted but not reported twice. Where a run sets `w:b`, `w:i` or `w:sz` but not their complex-script copies, these are added, since Word formats Kannada with `w:bCs`, `w:iCs` and `w:szCs`; `to-nudi` copies them the other way. Tracked deletions are converted too. Not done: bold, italic and sizes that come from styles, symbols inserted with `w:sym`, fonts of paragraph marks and styles, and parts written with a namespace prefix other than `w:`.
- **DOC.** `to-unicode` reads Word 97 to 2003 `.doc` files and writes their text to `NAME.doc.txt`, 1 line per paragraph, table cell or line break. The reader follows [MS-DOC]: the piece table, in both 8-bit and UTF-16 pieces, then the font of each character from the stylesheet defaults, the paragraph style and its bases, the character style, the run's own properties and the piece's own properties, each over the last. Word draws a character below U+0080 in the run's ASCII font and others in its high-ANSI font, and the reader does the same. Runs in a legacy font are converted in that font's layout, and the Nudi `k` fonts give Kannada digits; other runs are kept. A symbol font's codes, which Word stores at U+F020 to U+F0FF, are read as their byte, and a character with no Windows-1252 byte, such as Unicode Kannada typed while a Nudi font was chosen, is kept as it is. Field instructions and tracked deletions are left out, and field results and hidden text kept. A symbol inserted with Insert Symbol is read in its own font. List numbers and bullets, which Word draws and does not store as text, are not in the output. Footnotes, headers and footers, comments, endnotes and text boxes follow the body, each after a blank line; a header or footer that several sections repeat is written once. Report rows give the line in `NAME.doc.txt`. Legacy fonts with no table, such as Shree-Kan-0851, are reported and their text left out. Word 6 and Word 95 files and password-protected files are refused with a reason. [docs/doc-rtf.md](doc-rtf.md) has the method and results on public documents.
- **RTF.** `to-unicode` reads `.rtf` files and writes their text to `NAME.rtf.txt`, as for DOC files. The font table gives each `\fN` its name; `\plain` returns to the `\deff` font. `\'hh` bytes and 8-bit text are read as Windows-1252, which keeps legacy glyph codes as typed, and `\uN` is read as Unicode, skipping the `\ucN` fallback after it. Tracked deletions (`\deleted`) and list numbers (`\listtext`, `\pntext`) are left out, as for DOC. A surrogate pair written as 2 `\u` values gives 1 character, and a `\u` value above 65535 is read as a code point. Field instructions, pictures, `\bin` data, the stylesheet and other destinations with no document text are skipped, as are unknown destinations marked with `\*`; of a `\upr` group, only the Unicode copy in `\ud` is read. Footnotes, headers and footers, comments and text boxes (`\shptxt`) become their own parts of the output, as for DOC. Not done: `\'hh` text in non-legacy fonts set in a code page other than Windows-1252 is read as Windows-1252 too.
- **PDF.** `to-unicode` reads PDF files and writes their text to `NAME.pdf.txt`, with text in legacy fonts converted, Nudi B-Akshara, Kan-Eng, Akruti and Shree-Lipi included. Text that is already Unicode is kept whole, conjuncts included, and glyphs it cannot read are reported. Legacy fonts are found by name, or by their text when the PDF hides the name. A font whose codes were renumbered is read through its ToUnicode map when the map gives the codes back. Other renumbered fonts, and legacy fonts in layouts without a table, such as Shree-Kan-0851, are reported and left out. [docs/pdf.md](pdf.md) has the method and results on public PDFs.
- **Legacy font names.** The tool knows the ANSI Nudi fonts (Nudi 01 e to Nudi 05 k, Nudi Akshara) and Baraha's BRH fonts for Kannada, in the Nudi layout, Nudi B-Akshara (NudiB-Akshar) and the Kan-Eng fonts (Kan-EngPraja, Kan-EngDeepa and the others named Kan-Eng), each in its own layout, AkrutiKndPadma and its weights, in the Akruti layout, and Shree-Kan-0850, in the Shree-Lipi layout. Other Shree-Kan fonts are known as legacy fonts with no table. `--legacy-font "NAME=akruti"` adds another in the layout named after `=`; with no `=`, it is in the `--layout` layout. `to-unicode --layout nudi-b`, `--layout kan-eng`, `--layout akruti` or `--layout shree-lipi` reads text files in that layout; the default is Nudi. `to-nudi` writes Nudi only.
